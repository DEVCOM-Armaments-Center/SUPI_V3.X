# sUPI Firmware

The small Universal Payload Interface (sUPI) is meant to connect a payload to a small (4-6") drone, providing connectivity
for power, communication, and control.  The platform side of the sUPI consists of an arrowhead-shaped wedge and
a circuit board with a microcontroller, load switch, and signal pathways.  The payload side has a corresponding latching
receiver and a circuit board with a voltage regulator and solder pads for the payload cable harness to attach.

This folder holds the firmware for the platform-side microcontroller.

## Features

The firmware is responsible for controlling the load switch that delivers power to the payload.  The microcontroller
will regularly probe for the presence of a payload and the load switch will only be enabled when and for as long as
the payload is positively detected.  The microcontroller will also monitor the current being delivered to the
payload and will disable the load switch if the current exceeds a safe level (most likely due to a short circuit).
Finally, the microcontroller may be connected to a data bus on the platform to override these controls and provide
status information.

### Payload detection

To be automatically detected, payloads must be equipped with a One-Wire chip (e.g. DS2431 EEPROM).  (The platform
board provides a solder bridge to force the load switch to turn on for other payloads.)  The microcontroller will
check for the presence of the One-Wire device at regular intervals (presently every 50 milliseconds) and (de)assert
the load switch enable after a run of multiple (presently five) identical results (found or not found).  This
makes the payload detection relatively tolerant of momentary interruptions during initial connection or in the event
of a crash while still responding within 300 milliseconds.

The STM32C011 microcontroller on the platform board does not have a native One-Wire peripheral so this signaling
must be generated by firmware.  One-Wire requires accurate timing on the order of microseconds so timers and
interrupts are used to provide consistency.  Timer and GPIO registers are accessed directly instead of through
HAL functions to meet timing requirements.

Payload detection is performed by executing a reset pulse (data line pulled low for 500 microseconds) and waiting
for a slave device presence pulse.  If the slave device responds by driving the presence pulse, the payload is known
to be connected.  Control of the pin is switched between GPIO and timer as needed.  Two timers are used, one for interval
timing and the other for input capture (detecting the presence pulse).
These roles could be performed by a single timer, but the overhead of switching
between the configurations makes this difficult as the transition time between releasing the data line and
becoming sensitive to the presence pulse is only a few microseconds.  Edge detection in hardware is preferred to
sampling the levels in firmware as it can be done without requiring the unbroken attention of the microcontroller.

### Payload identification

Since an EEPROM is used for the payload detection feature, this could also be used to detect individual
payloads by type, serial number, or some other attribute.  One application of this feature would be to
determine the maximum allowable current for a payload, e.g. if one of the interface pins was not populated.
The One-Wire implementation does not include read/write capabilities or an implementation of the EEPROM
protocol so some effort would be required to add this functionality.

### Current monitoring

An ACS711 Hall-Effect current monitor chip in the power path is used for accurately measuring the current being
delivered to the payload.  This is connected to an ADC input on the microcontroller.  An ADC watchdog will
trigger an interrupt if the ADC values move outside a certain range, allowing an interrupt to disable the load
switch within microseconds of the fault (such as a short) being detected.  A software-based "slow blow fuse" can also be enabled
which will disable the load switch if too much current is detected over a millisecond-scale interval, allowing some
protection while tolerating in-rush current.

### Platform communication

The platform board brings out pins from the microcontroller that can be assigned to either UART or I2C.  These are
intended for integration with a bus on the flight controller, allowing status reporting, configuration and/or control of the payload
power system.
